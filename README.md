# デジタル得点表（point-checker）

紙の「得点表」「分野別チェック」で行っている得点記入を、Web上で行うためのアプリです。
Firebase（Hosting・Authentication・Firestore）で動きます。ビルド作業は不要です。

![生徒の記入画面](docs/student-sheet.png)

## できること

### 用語
- **テスト**：1回分の問題（問題番号・分野・配点）です。例：「第1回 数学Ⅰ・A」
- **セット**：テストをまとめたものです。例：「セット1」＝第1回＋第2回、「数学ⅠA 全体」＝第1回〜第14回
- **分野**：タブ（共通テスト専用得点表／その他の演習）ごとに1つのリストがあり、そのタブのすべてのテストで使い回します

### 生徒
- **ログイン**：出席番号（4桁）・名前・パスワードでログインします。初回は先生から受け取った仮パスワードを自分のパスワードに変更します。
- **2つのタブ**：「共通テスト専用得点表」と「その他の演習」に分かれています。
- **テストへの記入**：問題ごとに点数を入力すると、自動で保存されます（Enterで次の欄へ）。振り返りメモも書けます。
- **目標点**：
  - 共通テスト：100点満点あたりの目標点を1つだけ決めます。各テストの満点に換算して「達成」「あと○点」と表示します（200点満点のテストなら2倍）。
  - その他の演習：テストごとに目標点を決めます。
- **テストごとの結果**：得点・得点率・クラス平均・順位・偏差値、分野別の結果、**得点分布**（自分のいる区間に「あなた」と表示）を見られます。
- **セットごとの結果**：まとめたテストの一覧、セット全体の**分野別チェック**と得点率の分布を見られます。

### 先生
- **ログイン**：メールアドレスとパスワードでログインします（登録時にメールの確認あり。パスワードを忘れたらメールで再設定）。
- **分野**：タブごとに分野リストを作り、すべてのテストで使い回します。
- **テスト**：テストを作成・編集・**複製**できます。複製すると、名前の数字が自動で次の番号になります（第1回 → 第2回）。問題を追加すると、番号と分野・配点が前の行から自動で入ります。
- **選択問題**：「第4問〜第7問から3問選択」のような問題に対応しています。
  - テストの編集画面で「選択グループ」を作り、問題ごとに「必答」かそのグループかを選びます。
  - 大問は問題番号の先頭でまとまります（4-1・4-2 → 第4問）。
  - 生徒は大問ごとに「選択」にチェックを付けて記入します。選べる数に達すると、ほかの大問は選べなくなります。チェックを外すと、その大問の点数は消えます。
  - 満点は、必答と選ぶ数ぶんの大問で数えます。「全問記入」は、必答すべてと、決められた数の大問を記入した状態です。
  - 分野別の結果は、その分野を選んだ人どうしで比べます。
- **セット**：テストを選んでセットを作ります。
- **生徒の画面を試す**：生徒と同じ画面で記入を試せます（保存はされません）。
- **成績一覧**：テストごとに問題別・分野別、セットごとにテスト別・分野別で表示します。得点分布、CSV出力、出席番号での絞り込みもできます。
- **点数の修正**：生徒の記録を開いて「この生徒の点数を修正する」を押すと、先生が記入・修正できます。
- **アカウント管理**：生徒アカウントを「出席番号,名前」の貼り付けで一括作成できます。先生として登録できるメールアドレスの一覧と、生徒の自己登録（オン・オフ）も管理します。
- **以前の形式からの変換**：以前の「得点表」（中にセットがある形式）があると、管理画面に変換ボタンが出ます。変換の内容は次のとおりです。
  - 回 → テスト
  - 得点表の中のセット → セット（得点表全体のセットも作ります）
  - 記入済みの点数は引き継ぎます。目標・メモは引き継ぎません。

## ファイル構成

```
public/              ← Firebase Hosting で公開するファイル
  index.html
  app.css
  app.js             ← 画面と処理
  stats.js           ← 集計（平均・順位・得点率）
  firebase-config.js ← ★ 自分の Firebase の設定を書く
firestore.rules      ← セキュリティルール（誰が何を読める・書けるか）
firebase.json
.github/workflows/deploy.yml ← main への push で自動デプロイ
functions/           ← 任意: パスワード再発行用の Cloud Functions（Blaze プランが必要）
```

## セットアップ手順

Firebase プロジェクトは `point-check-9ca84` です。設定値は `public/firebase-config.js` に書き込み済みです。
公開後のURLは **https://point-check-9ca84.web.app** になります。

### 1. Firebase プロジェクト
プロジェクトとウェブアプリの登録は完了しています。Google アナリティクスは、このアプリでは使いません。

### 2. ログイン方法を有効にする
「Authentication」→「始める」→「Sign-in method」で **メール / パスワード** を有効にします。

生徒はメールアドレスを使いません。出席番号を `s3101@score-note.local` という形に変換して内部で使います。先生は自分のメールアドレスを使います。

### 3. Firestore を作る
「Firestore Database」→「データベースを作成」で作成します。

- ロケーション：`asia-northeast1`（東京）がおすすめです。
- モード：本番環境モードを選びます（ルールは後でデプロイします）。

### 4. デプロイする

#### A. GitHub から自動でデプロイする（おすすめ）
`main` ブランチに push するたびに、GitHub Actions（`.github/workflows/deploy.yml`）が Hosting と Firestore ルールをデプロイします。
最初に一度だけ、Firebase へのデプロイに使う鍵を GitHub に登録します。

1. Firebase コンソール → ⚙「プロジェクトの設定」→「サービス アカウント」→「新しい秘密鍵を生成」で JSON ファイルをダウンロードします。
2. GitHub のリポジトリ → Settings → Secrets and variables → Actions → **New repository secret** を開きます。
   - 名前：`FIREBASE_SERVICE_ACCOUNT`
   - 値：ダウンロードした JSON の中身をすべて貼り付けます。
3. Google Cloud の IAM（https://console.cloud.google.com/iam-admin/iam?project=point-check-9ca84）で、鍵のサービスアカウント（`firebase-adminsdk-…`）に「Firebase ルール管理者」のロールを追加します（Firestore ルールのデプロイに必要）。
4. Actions タブで「Firebase にデプロイ」を選び、**Run workflow** を押します（以降は push するたびに自動で動きます）。

ダウンロードした鍵ファイルはプロジェクトの管理者権限を持つので、リポジトリには入れず、登録後は削除してください。

#### B. 自分のパソコンからデプロイする
```bash
npm install -g firebase-tools
firebase login
firebase deploy --only hosting,firestore:rules
```

### 5. 最初の先生アカウントを作る
1. Firebase コンソールの「Firestore Database」で「コレクションを開始」を押し、コレクションIDを `config` にします。
2. ドキュメントIDを `teachers` にし、次のフィールドを1つ作って保存します。
   - フィールド名 `emails`、型 **array**、値に自分のメールアドレス（**小文字**）を1つ（型は string）
3. アプリを開き、「先生」タブ →「先生の新規登録」から、名前・そのメールアドレス・パスワードで登録します。
4. 届いた確認メールのリンクを開き、アプリに戻って「確認しました」を押すと、先生として使えるようになります。
5. ほかの先生は、アプリの「生徒・アカウント」画面の「先生として登録できるメールアドレス」に追加すれば、同じ手順で登録できます。

確認メールは Firebase から送られます。届かないときは迷惑メールフォルダを確認してください。

## 使い方の流れ

1. **分野を決める**（先生）
   得点表の管理画面でタブ（共通テスト／その他の演習）を選び、「分野」に使う分野を追加して保存します。
2. **テストを作る**（先生）
   「テストを作る」から問題（番号・分野・配点）を入力し、「生徒に公開する」をオンにして保存します。
   **公開するまで生徒の画面には表示されず、記入もできません。**
   2回目以降は「複製」で作ると早いです。
3. **セットを作る**（先生・任意）
   「セットを作る」からテストを選んでまとめ、公開します。
4. **生徒のアカウントを作る**（先生）
   「生徒・アカウント」で「出席番号,名前」を1行に1人ずつ貼り付けて作成し、初期パスワードを配ります。
5. **記入する**（生徒）
   ログインしてテストを開き、点数を入れます。共通テストはホームで目標点を1つ決めておきます。
6. **確認する**（先生・生徒）
   テストやセットの成績一覧、分野別の結果、得点分布を確認します。

## 集計のルール
- **得点率**：記入済みの問題の得点 ÷ 記入済みの問題の満点です。進み具合が違う生徒どうしでも比べられるようにしています。
- **テストの平均・順位・得点分布**：そのテストを全問記入した生徒どうしで、合計点を比べます。
- **セット・分野の点数の分母**：記入した問題の満点です（例：2テスト中1テストだけ記入なら「88 / 100（満点 200）」）。選ばなかった選択問題は満点に入れず、「未選択」と表示します。
- **セット・分野の順位と分布**：1問以上記入した生徒どうしで、記入済みの問題の得点率を比べます。
- **偏差値**：50 + 10 ×（自分 − 平均）÷ 標準偏差で計算します。同点の場合は同じ順位になります。
- 先生は集計に含みません。

## データとプライバシー

| データ | 生徒本人 | 他の生徒 | 先生 |
|---|---|---|---|
| 名前・出席番号・メールアドレス（`users`） | 読める | **読めない** | 読み書きできる |
| 点数（`scores`） | 読み書きできる | 名前なしで読める※ | 読み書きできる |
| テストごとの目標・振り返りメモ（`notes`） | 読み書きできる | **読めない** | 読める |
| 共通テストの目標点（`goals`） | 読み書きできる | **読めない** | 読める |
| テスト・セット（`tests` / `sets`） | 公開中のものを読める | 同左 | 読み書きできる |
| 分野リスト（`fieldLists`） | 読める | 読める | 読み書きできる |
| 先生として登録できるメールアドレス（`config/teachers`） | 読めない | 読めない | 読み書きできる |
| 生徒の自己登録のオン・オフ（`config/settings`） | 読める | 読める | 読み書きできる |

※ 平均点・順位・得点分布をブラウザ側で計算するため、点数データは名前を含まない形で他の生徒からも読める設定です。画面には他の人の点数は表示しません。
これも見せたくない場合は、集計を Cloud Functions で行う構成に変更できます（Blaze プランが必要）。

## 任意: パスワード再発行（Cloud Functions）
無料の Spark プランのままでは、先生の画面から生徒のパスワードを再発行できません。

**再発行できるようにする場合**（Blaze プランが必要。この用途なら通常は無料枠内に収まります）：
```bash
cd functions && npm install && cd ..
firebase deploy --only functions
```
デプロイ後、`public/firebase-config.js` の `functionsEnabled` を `true` にして、もう一度 `firebase deploy --only hosting` を実行します。
「生徒・アカウント」画面に「パスワード再発行」ボタンが出るようになります。アカウントを削除したときに、ログイン情報も一緒に消えるようになります。

**Functions を使わない場合**：
1. Firebase コンソールの Authentication でその生徒を削除します。
2. アプリで同じ出席番号のアカウントを作り直します。

この場合、以前の記録は引き継がれません。

## ローカルで試す（エミュレーター）
```bash
firebase emulators:start --only auth,firestore,hosting --project demo-score
```
- `http://localhost:5000` を開くと、自動でエミュレーターに接続されます。
- 最初の先生は、エミュレーターUI（`http://localhost:4000`）の Firestore で `config/teachers` を作って登録します。確認メールのリンクはエミュレーターUIの Authentication に表示されます。
- エミュレーターを使うには Java が必要です。
